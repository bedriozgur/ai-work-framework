# Troubleshooting Pattern

1. Define the symptom precisely.
2. Capture a baseline before changing anything.
3. Separate observed facts from hypotheses.
4. Identify the smallest discriminating test.
5. Prefer non-destructive evidence collection first.
6. Make one bounded change when possible.
7. Verify whether the symptom changed.
8. Record failed hypotheses when useful to prevent repetition.
9. Update current state only after verification.
10. Leave a concrete next test or action if unresolved.

For production-impacting actions, obey project approval rules.
